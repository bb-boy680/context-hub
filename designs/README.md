# Context Hub · 设计说明

统一管理 **Skills / Rules / Plugins / MCP 服务器 / Prompts·AGENTS.md** 五类资产。宿主是 DeepSeek Harness（DSH）插件内的页面，沿用 DSH 暗色语义 token，组件沿用 shadcn-ui 构件约定。

画布：`designs/design.pen`（23 块画板，1440×900 为主；分组见 §2）。本文件不含实现代码。

## 1. 导航

二级导航胶囊出现在每个 Context Hub 页面，是唯一一级入口：

```
侧栏 248px │ 顶栏 52px（面包屑 · 摘要 · 搜索 · 次操作 · 主操作）
           │ 二级导航 44px：(总览)(Skills 24)(Rules 12)(Plugins 13)(MCP 5)(Prompts 12)  [全局│本工作区]
           │ 页面内容：视图页签 → 两条筛选行（右端为页面主操作）→ 卡片网格 / 列表
           │ 页脚：同步状态 · 上下文预算
```

六项任意互跳，`总览` 为枢纽（统计卡右上角 `›`）。作用域开关统一放导航右侧。

### 顶栏：所有列表页共用的同一个 shell 构件

```
Context Hub  ›  <页面名>  <摘要>                    [搜索 + Ctrl K]  [⟥ 远程仓库]  [⟳ 同步]
```

| 区 | 内容 |
| --- | --- |
| 左 | `Context Hub` 15/600 · `›` 13 `#8B96A5` · 页面名 13 `#A5B0BD` · 摘要 11.5 `#8B96A5`；总览是枢纽、不带面包屑，摘要直接跟在标题后 |
| 右 | 搜索框（`#151D28` 底 + 0.5px `#FFFFFF1F` 描边 + r8）内嵌 `Ctrl K` 角标 · `远程仓库` 次按钮（`git-branch`）· `同步` 主按钮（`refresh-cw`，`#3D7BFF`） |
| 几何 | 高 52 · `gap 10` · `padding [0,20]` · 仅下边框 0.5px `#FFFFFF12` |

**为什么每页动作完全一样**：`同步`（作用于全部工作区）与 `远程仓库`（全库唯一的远程连接）是**全局动作**，不该随页面变；页面级的新建动作因此全部下移到各页自己的工具行右端。这样顶栏只剩页面名与版面摘要两处差异。

搜索框宽度由列宽决定：1192 → 300。**主列一律 1192**——详情不再占侧栏，而是居中弹窗（§3e）。

顶栏不再放胶囊徽标：同一个胶囊过去在总览/作用域页表示**作用域**（`全局`）、在 Skills/Plugins/MCP 表示**视图模式**（`卡片视图`），而视图切换在页面工具行里本来就有；作用域状态改由二级导航右侧的 `全局│本工作区` 开关表达。

## 3. 卡片图片区（当前方案）

Skills / Plugins / MCP 三页共用同一形态：**一张 16:9 封面**，图片区高 150，圆角随卡片 14，`clip` 让封面贴合上圆角。Rules 卡片没有截图，**一律**走文档封面；Prompts 与 Skills 同构（可上传封面，未上传时渲染片段内容）——见 §3e。

| | 有图片 | 没有图片 |
| --- | --- | --- |
| 内容 | 单张封面（16:9） | 该资产的文档 **markdown 渲染** |
| 左上角标 | `已上传` | `SKILL.md` / `README.md` / `工具清单` |
| 右上角 | 更多菜单（MCP 为连接状态徽标） | 同左 |
| 左下 / 右下 | 类型图标 + `16:9` | — |
| 文档内容 | — | Skills→SKILL.md、Plugins→README.md、MCP→工具清单 |

**文档封面的逐段模糊**：把文档切成 4 条 32px 横带，每条渲染同一份内容的对应切片，模糊半径与不透明度逐段递增，形成"越往下越糊、越淡"的退场：

| 段落 | 模糊 | 不透明度 |
| --- | --- | --- |
| 1（最上） | 0 | 1.0 |
| 2 | 2px | 0.82 |
| 3 | 4px | 0.55 |
| 4（最下） | 7px | 0.30 |

实现要点：内层放整份内容的副本，用 `clip` 的横带做窗口，`y = -32 × 段序`；模糊加在内层内容上而不是横带上，否则边缘会溢出。

填充：有图 `linear-gradient(180°, accent 90% → accent 35% 55% → #141B26)`；文档封面用中性深色渐变 `#171e27 → #0e131a`。**40px 量级的缩略图不要用网格渐变**（深色顶点被放大，看起来像空框）。

卡片尺寸：Skills 4 列 × 266 宽；Plugins / MCP 3 列 × 246 宽（右侧保留详情 / 工具面板）。

## 3b. Skills：归类 / 同步 / 下载

**归类**。筛选行有 `分类 全部 ▾` 下拉，值域见 §3e 的八字词表（三类资产共用）。每一处都显示归属：卡片在第三行**第一枚**胶囊；列表在**名称单元格尾部**挂同一枚胶囊——单元格里的名称块是 `fill_container`，所以追加进去会自动右对齐，等于多出一列"分类"，且完全不必动表头。

**同步 / 待更新**。远程有新版时：

| 视图 | 待更新信号 | 更新动作 |
| --- | --- | --- |
| 卡片 | 元信息文本换成琥珀色 `⟳ 更新 vX.Y.Z` 按钮 | 点该按钮 |
| 表格 | 名称单元格加 `待更新` 胶囊 | `更新` 列的时间文本换成 `⟳ 更新` 按钮 |

**一键全部更新**。筛选行右端 `⟳ 全部更新 (2)`：琥珀描边 + 计数胶囊，点击后扫描全部 skill、把需更新的批量更新（⑧ 状态集可再补一次执行中进度态）。计数为 0 时应转为幽灵态而不是消失，位置不跳。

**下载**。入口是各视图 tabs 行右端的 `☁ 下载`，打开画板 ⑩：搜索 skills.sh + 归类筛选胶囊 + 结果列表（归类胶囊 / 仓库 / 下载量 / 版本 / `下载` 按钮 / 已安装时显示 `✓ 已安装`）+ 页脚 `下载 N 个`。下载后写入 `.dsh/skills/`，与已安装同名时覆盖并提示。

## 3c. Skill 详情弹窗与 MarkdownEditor

点卡片或行打开的是**居中弹窗**（1040×640），不再是侧边抽屉。抽屉只能给表格主列留 420px，文件树 + 编辑器根本放不下；而且"编辑一个对象"本身就是模态语义。两个 tab：

| tab | 内容 |
| --- | --- |
| **配置** | 封面（16:9 预览 + 缩略图排序 + 拖入/点击上传，`PNG / JPG / WebP · 单张 ≤ 2MB · 可多选`）+ 分类标签（可移除的已选胶囊 + 待选胶囊 + `新分类名称` 输入 + `+ 添加`，词表见 §3e）。**不含生效工作区**——作用域统一由作用域矩阵批量挂载，页脚用一行灰字交代去向 |
| **文件内容** | 左侧 260px 文件树（`SKILL.md` + `references/` `scripts/` `assets/`），右侧编辑器 |

两 tab 共用头部（类型图标 · 名称 · `内置 · v1.2.0 · 4 张图片 · 4.2 KB` · `已启用` · 关闭）与页脚（`取消` + `保存`）。

**MarkdownEditor** 是 `.pen` 里 `reusable: true` 的组件（id `JIhQu`），⑥ Prompts 与 ⑪ 详情弹窗共用同一套 anatomy：

```
[文件树 260px] │ [工具条 44px：类型图标 · 文件名 · 已修改胶囊 · 编辑|预览|差异 · 保存]
               │ [代码区：行号列 22px（11px JetBrains #8B96A5）+ 内容列（11px JetBrains，lineHeight 1.7）]
               │ [状态栏 32px：行 N–M / 共 K 行 · Markdown · UTF-8 · LF]
```

- 着色：frontmatter 键 `#82ABFF`、`---` 与行号 `#8B96A5`、代码正文 `#A5B0BD`、标题 `#EEF2F7`/600
- 分段控件：轨道 `#151D28` + 0.5px `#FFFFFF1F` 描边、padding 2；激活段 `#1B2431` 底、文字 `#EEF2F7`/500，其余段文字 `#A5B0BD`
- 未保存时文件名右侧出现 `已修改` 胶囊（`#E0A32A24` / `#E0A32A`）
- 宽度由容器决定；文件树宽度是唯一参数（详情弹窗与 Prompts 都用 260）

**尚未落地的一步**：⑥ Prompts 里仍是这份编辑器的**副本**，没有改成 `ref` 实例。`ref` 的自定义要写 `descendants` 的「id 路径」，而该路径语法没有文档；加上 Prompts 的头部是 `全局 / AGENTS.md` 面包屑、状态栏是 `1.8k / 8k tokens · 16 行 · 中文 62% · 格式化`，与详情弹窗不同，必须逐节点覆写——在路径语法确认前盲改的风险大于收益。

## 3d. 两个视图：容器与分页

同是 Skills，**卡片视图没有容器、表格视图有**——这不是疏漏，是两者结构不同：

| | 卡片视图 | 表格视图 |
| --- | --- | --- |
| 外框 | **无**。卡片自身就是"面" | **有**区域框（平色 `#111721` + 0.5px 发丝线） |
| 为什么 | 再套一层就是"卡中卡"：多一条边框、多一次留白，却不增加信息；而且两组渐变互相抵消，卡片反而陷进背景 | 表格由行分隔线组成，**行线必须依附外框才有归属**，否则直接落到底色上读成"悬空的线"；吸底页脚也需要一条可依附的边 |
| 每页 | 8 个（2 行 × 4） | 13 条 |
| 为什么是这么多 | 卡片高度被 **16:9 封面**锁死（一行 239px 不可压缩），区域只放得下 2 行 | 行是**可压缩的重复单元**，页高决定条数：`(688 − 34 表头 − 46 页脚) ÷ 46 = 13.2 → 13` |
| 剩余高度 | 152px，落在网格与页脚之间 | 10px，落在末行与页脚之间 |

**留白要留在容器外。** 同一块空白，落在容器**里**读作"没填满"（缺陷），落在容器**外**读作"页边距"（有意）。所以表格把 10 条补到 13 条**填满面板**，卡片视图则把页脚**吸到底**、让剩下的 152px 成为网格与页脚之间的边距——而不是上一版那样把页脚悬在页面中间、空白留在它**下面**。两页的页脚现在都在内容区底部收边（表格 876、卡片 890），都是贴底状态条。

> 想把卡片网格也填满，只有两条路：3 行需要单卡降到 ≤ 205px（等于放弃 16:9 封面），或每行改 5 列（单卡降到 217px 宽）。两条都要动卡片 anatomy，未做。

| 行尾动作 | 启用开关 | 启用开关 | 启用开关 | **安装**（→ 目标菜单，每行带 `⋯`，见下） |
| 面板页容量 | 24 条 → 每页 13 | 12 条 + 一行「新建规则」→ 13 行 | 13 个 → 每页 13 | 12 个 + 一行「新建片段」→ 13 行 |

**配置弹窗分两种，按"资产有没有自己的文件内容"选。** Rules 与 Plugins 的配置 tab 是左边该类型自己的结构化字段（触发条件 / 包信息与权限）、右边它的正文/清单加分类标签；Skill 与提示词的配置 tab 只剩**归属**（分类标签）——**规则与插件的"内容"是宿主读的结构化配置，改的是字段；skill 与提示词的"内容"是一个 Markdown 文件，改的是文件**，所以正文不在这一 tab。v17 时 Skill 与提示词两栏同形（左边还多一张 16:9 封面上传区）；v18 把提示词那边的封面上传去掉，只留正文与标签。这正是 Prompts 一开始做错的地方：我照 Rules 的样子给了它"片段内容"输入框，而正文在该 tab 里本来就该是只读的文件。

### 分类：一套跨资产共用的词表

四类资产的**分类是同一套 8 个字**，不是各写一套：

```
发布与变更 · 代码质量 · 测试与自动化 · 接口与契约 · 数据与查询 · 文档与写作 · 安全与合规 · 平台与扩展
```

**为什么共用。** 分类回答的是「这个资产服务于哪项工作」，而同一项工作本身就跨类型：代码质量既有 `rule-ts-strict` 规则也有 `legacy-formatter` 插件，接口与契约既有 `openapi-diff` skill 也有 API 兼容规则。词表若各写一套，就无法回答「我在这项工作上装了哪些东西」；共用一套则学一次、处处能筛，将来也才可能在总览页按分类汇总。词表因此比「资产种类」更宽——`平台与扩展` 同时容纳 skill（`plugin-authoring`）、插件（`dsh-context-hub`、`dsh-k8s`）与 `AGENTS.md`。

**分类出现在四处**（四类一致）：筛选行的 `分类 · 全部` 下拉、卡片第三行的**第一枚**胶囊、列表名称列尾部的胶囊、配置弹窗的 `分类标签` 区（可移除的已选 + 描边式待选 + `新分类名称` 输入 + `+ 管理分类`）。Skills 另有第五处：下载页的归类筛选。

**胶囊着色跟类型走，不跟分类走。** 分类胶囊的底色与文字取该页的**类型强调色**——Skills `#A78BFA`、Rules `#F0913E`、Plugins `#3D7BFF`、Prompts `#3ACBD4`。同一个「代码质量」在四个页面各是自己那页的色；代价是颜色不表示分类值，换来的是每页仍只有一个强调色（v12 定的规矩），不必为 8 个分类再维护一套色板。

**触发 / 权限 / 类型是另一根轴，与分类并存。** Rules 的 `触发`（提交前 / 编辑时 / 新建时 / 合并前 / 构建时）回答"什么时候生效"，Plugins 的 `权限`/`贡献项` 回答"它能动什么、提供了什么"，Prompts 的 `类型`（片段 / `AGENTS.md`）回答"它是内联片段还是一份完整约定文件"；这些都是该资产类型的**机制**，不是主题，所以两者并存而不是互相取代。为避免同页出现两枚同色胶囊，机制类胶囊统一走中性色（底色 `#1B2431`、文字 `#A5B0BD`），强调色只留给分类。

**排序键因类型而异，表头随之改。** 规则有优先级、提示词有注入顺序——都是"越靠前越先生效"的数字，所以两者共用同一套列表骨架，只把首列的**标题与含义**换掉（`优先级` / `顺序`），数字用 JetBrains Mono 等宽。Rules 的优先级越大越先生效，Prompts 的顺序越小越先注入。

### Prompts：交付出去，不是复制走

**v18 推翻了 v17 的结论。** 当时定的是「提示词是**取用**的（复制内容），不是**挂载**的（开关生效）」，
于是四类资产里只有 Prompts 把行尾动作做成了复制图标。实现这一版时用户改了口径：
提示词要**交付**——安装到某个 Agent 的目录、或从它生成一份 Rule / 一条 Commands。
复制图标随之取消。

那张判据表仍然成立，只是 Prompts 那格换了答案：

| 资产 | 行尾动作 | 为什么 |
| --- | --- | --- |
| Skills / Rules / Plugins | 启用开关 | 它们是**挂载生效**的——开就是让宿主加载它 |
| Prompts | **安装**（→ 目标菜单） | 它是**交付**的——内容要被写进某个 Agent 自己读的文件里 |

**「交付」是菜单，不是开关。** 提示词没有"启用/停用"两态：同一条提示词可以既在工作区的
`.claude/commands/` 里、又在全局的 `~/.claude/CLAUDE.md` 里，两者互不相干。
所以行尾是一个"装到哪儿"的列表，每行一个 Agent 位置，行内显示它是否已经在那儿。
这与 MCP / Plugins 的安装菜单是同一种形状，不是 Prompts 自己发明的。

**三种写法挂在 Agent 行自己身上。** 列表回答"装到**哪儿**"，而"装成**什么**"是另一根轴、
且每个 Agent 的答案不同（各家读的目录与文件名都不一样），所以每个 Agent 行的右侧带一个 `⋯`，
它的悬浮菜单是：

| 项 | 写什么 | claude-code 的落点 |
| --- | --- | --- |
| 安装 | 提示词原文，一个 `<名称>.md` | `.claude/commands/<名称>.md` |
| 生成 Commands | 同一个文件，但带 agent 读的 frontmatter | 同上（改写，不并排第二份） |
| 生成 Rule | 一份独立的规则文件 | `.claude/rules/<名称>.md` |
| 添加到 CLAUDE.md | 往记忆文件追一节，**同名分节替换而不是追加** | `~/.claude/CLAUDE.md` |

**最后一项只出现在全局行**，因为项目侧的 `CLAUDE.md` 是**别人也提交、也读**的文件：
用一个和"写自己私有记忆"一模一样的措辞去悄悄改共享文件，正是行与行之间该显形而不能藏的差别。
项目侧要留规则就写独立文件，那里不碰任何不属于自己的东西。
这项**不是为 claude-code 写的特例**：位置自己声明 `instructionFile`，声明了才出现这一项。

**页签只剩「全部」。** v16 / v17 给 Prompts 定的 `片段 / AGENTS.md / 工作区覆盖` 三个筛选胶囊一并取消：
它们筛的是"它是什么"，而现在这条轴由 `⋯` 菜单回答，页签上再放一遍是重复。
Prompts 也成了五类里唯一**没有页签轴**的一页——它没有"装没装"之外的状态可筛，
而"装没装"是逐 Agent 的，不是整行的属性。

**`顺序` 删掉了。** v17 保留它，理由是「多份 AGENTS.md 与 `@import` 的片段有注入次序」。
但注入次序是**宿主**的事，一条提示词被写进哪个文件、那个文件里它排第几，都不是 hub 能决定的；
表单里也没有这个字段，留一个只有设计稿存在的列就是空列。

**提示词没有标题，只有 `description`。** 四类资产里唯一不靠"名字"认人的一条：

| | Skills / Rules / Plugins | Prompts |
| --- | --- | --- |
| 身份字段 | `name`（人类可读的名字） | **`description`**（一句话说明这条是干什么的） |
| 正文 | 另有一份结构化内容或清单 | `prompt`，就是它自己 |
| 屏幕上 | 名称用等宽字（它也是文件名） | description 用**正文字体**——它是句子，不是文件名 |

三处身份一起跟着 description 走，这也是它**必填**的原因：投递出去的文件名、`CLAUDE.md`
里那一节的幂等标记、库里"两条是不是同一条"的判据，全都由它算出来。
卡片上它当标题（名称行的位置），列表里它当首列——**删掉它，剩下的只有正文，而正文不是身份**。

`assets` 是库里保留但没人写的字段：一条提示词就是它的文本，没有图可传。
留着它是因为**库文件是人手写的**（本仓根的 `prompts.json` 就是先有的那份），
写回时丢掉一个自己不认识或暂时没用的字段，等于丢人的数据。

### 配置弹窗分两种，按"资产有没有自己的文件内容"选

Skills 与 Prompts 的配置 tab 曾经是**同一种**——左边一张 16:9 封面上传区、右边分类标签。
v18 把 Prompts 的封面换成**正文预览**：一条提示词就是它的文本，没有图可传。
判据不变（"内容是一个 Markdown 文件的，配置 tab 只剩外观与归属"），只是 Prompts 的"外观"没有了。

**13 行是算出来的，不是凑的。** 面板 688px，减去 34px 表头与 46px 页脚后剩 608px，按 46px 行高得 13.2 → 13 行。所以 Rules（12 条）与 Prompts（12 个）的第 13 行做成动作行（`+ 新建规则` / `+ 新建片段`），与卡片视图末尾的虚线磁贴同义，同时把面板填满（否则留 56px 空洞，见 §3d）；Plugins 则把数据集定为 13 个以满足容量。导航胶囊里的计数出现在 10 处导航行与总览统计卡上，改一次要全改——「一个事实只有一个出处」的反面教材，已在实现时统一。总览页的资产总数为 `66`（24 + 12 + 13 + 5 + 12，与五类计数一致）。

### MCP：添加流程

MCP 的卡片网格末尾是虚线磁贴 `添加 MCP 服务器 · stdio / http / sse`，点开 ⑤b 的对话框（640×572）：

```
[传输方式：stdio │ http │ sse]        分段控件，决定下面出现"命令"还是"URL"
名称        github                    ← 值会进入工具名前缀 mcp__github__…
命令        npx -y @modelcontextprotocol/server-github
参数        （可选，每行一个）
环境变量    KEY=VALUE 每行一个        ← 值写入凭据存储，不落盘到配置
[测试连接]  ✓ 已连接 · 发现 12 个工具
```

**只提供能验证的东西。** `测试连接` 不是装饰：MCP 客户端的失败模式是"配错了要到会话里才发现"，所以这里先探一次并回显发现的工具数——这也是卡片上 `连接异常` 徽标与 `重连` 动作的来源。连接失败**不阻止添加**（页脚写明），之后可在卡片上重连；这与 §3c 里"保存失败不丢编辑"是同一种态度。

**名称即命名空间。** 输入框旁的提示说明它进入 `mcp__<serverName>__<toolName>`，因为这个名字是**稳定契约**——改变它等于改变模型看到的工具名，会话历史与权限规则都会失配。所以名称字段是添加后不可改的（配置里只显示，不给编辑入口）。

## 4. 设计 token

| Token | 值 | 用途 |
| --- | --- | --- |
| surface-sidebar / page / region / sunken / raised | `#090C11` / `#0C1015` / `#111721` / `#151D28` / `#1B2431` | 侧栏 / 内容 / 容器区 / 输入框与分段轨道 / 行与胶囊 |
| hairline-subtle / default / strong | `#FFFFFF12` / `#FFFFFF1F` / `#FFFFFF2B` | 分隔线 / 输入框 / 虚框（一律 0.5px） |
| text-primary / secondary / tertiary / faint | `#EEF2F7` / `#A5B0BD` / `#8B96A5` / `#6E7B8B` | 标题与数值 / 说明 / 辅助 / 行号与禁用 |
| brand / brand-text / brand-button | `#3D7BFF` / `#6E9BFF` / `#2F6CE8` | 进度与强调 / 链接与活跃文字 / 白字按钮底色 |
| success / warning / danger / info | `#45C46B` / `#E0A32A` / `#F2554D` / `#3ACBD4` | 状态语义 |

**面分两层：对象与区域。** 对象（卡片、弹窗、浮层）自带 `linear-gradient(180°, #1B2432 → #141B26)` 加发丝线，弹窗再叠 `0 28px 72px #000000B8`；区域（装内容用的容器，目前只有 Skills 表格的外框）用平色 `#111721`，不渐变。两者亮度有序：页 `0.0051` < 区域 `0.0084` < 卡片 `0.0172`（相对亮度）。

> 上一轮我把同一套"卡片材质"无差别刷到了 63 个面片上，表格容器也在其中，于是容器和卡片长得一模一样、表格读起来像"一张巨卡里装着十几行"。**容器是区域，应比对象安静一档**——区域用平色，纹理留给对象。

1px 实色深灰描边在深色底上读作"硬边框"，是本设计上一版的"平"感来源，已全部换成 0.5px 半透明白。

类型强调色：Skills `#A78BFA` · Rules `#F0913E` · Plugins `#3D7BFF` · MCP `#45C46B` · Prompts `#3ACBD4`。派生底色用 8 位 hex（`#A78BFA26` ≈ 15%）。每页只允许**一个**强调色出场，承担分类胶囊与活跃态；机制类胶囊（触发 / 权限 / 贡献项 / 来源）一律中性（`#1B2431` / `#A5B0BD`），避免同页两枚同色胶囊抢读（§3e）。

字体 `Noto Sans SC` / `JetBrains Mono`；字阶 **30 / 20 / 17 / 15 / 13 / 11.5 / 10.5**（上一版的 9 个字号里 10/10.5/11/11.5 挤在 1.5px 内，肉眼读不出层级）；圆角 4/6/8/14/16/999（4 微件、6 行与输入、8 控件、14 卡片、16 弹窗、999 胶囊）；间距 4–32；命中区 ≥ 28px（表格行 46px）。

正文与背景的对比度按 4.5:1 逐条核对：1455 条文本平均 8.49:1，低于 4.5 的只剩代码行号（`#6E7B8B`，4.42，有意压暗）一类。

  - 这一轮暴露的是一类错：**"复制取用"和"交付"都能解释"提示词不是开关"**，
    而两者要写的代码完全不同。v17 只问了"它有没有启用态"，答案是没有，于是选了复制；
    真正该问的是"**这条内容最终去了哪**"——去了别人的文件里，那就是交付。
    设计稿给的是形态，不是数据流；数据流的答案只能从"这个特性能被谁消费"里问出来。
